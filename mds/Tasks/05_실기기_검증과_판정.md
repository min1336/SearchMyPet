# Task 05 — iOS 실기기 검증과 기술 Go/No-Go 판정

## 목적

컴파일 또는 XR Simulation 통과를 실기기 AR 통과로 오인하지 않고, 재현 가능한 증거로 `Wall Placement Technical Go (iOS)`의 완료 여부를 판정한다. Task 00에서 Android 우선으로 결정한 경우에만 제목과 매트릭스의 1차 플랫폼을 ARCore로 바꾼다.

## 작업

- [ ] iOS ARKit 실기기에서 밝은 질감 벽을 사용해 배치·이동·재관찰 시나리오를 연속 5회 실행한다.
- [ ] 밝은 단색 벽, 저조도 또는 반사 벽에서 탐지 지연/실패 시 안내 UX가 이해 가능한지 기록한다.
- [ ] 바닥·테이블에서 3회 시도해 배치가 거부되는지 기록한다.
- [ ] 권한 거부, AR 미지원(가능한 경우), tracking 제한, anchor 실패를 테스트 또는 코드 경로로 확인한다.
- [x] EditMode 단위 테스트(상태 전이·pose 계산)를 실행하고, 실기기 수동 검증과 별도로 기록한다.
- [ ] `git diff --check`와 Console 오류 수를 기록한다. 저장소가 아직 없다면 이 항목은 보류 사유를 기록한다.

## Go/No-Go 수용 기준

- [x] iOS ARKit 지원 실기기에서 수직 Plane을 탐지한다.
- [ ] 바닥·테이블은 어떤 경우에도 배치 후보가 되지 않는다.
- [ ] 유효 벽에서만 명확한 레티클과 배치 안내가 표시된다.
- [ ] 탭하면 축 규약과 offset에 맞는 캐릭터 1개가 생성된다.
- [ ] 5회 중 4회 이상에서 이동·재관찰 후 30초 동안 명백한 위치 이탈 없이 벽에 남는다.
- [ ] Reset/재배치 뒤 중복 인스턴스·anchor 누수·Console 오류가 없다.
- [ ] 기기 모델, OS, Unity/패키지 버전, 빌드 식별자, 환경, 영상/캡처가 기록되어 있다.

## 제외

다른 플레이어가 같은 장소에서 캐릭터를 발견하는 검증. 이것은 영속·공유 공간 앵커와 위치/콘텐츠 서비스가 필요한 별도 에픽이다.
