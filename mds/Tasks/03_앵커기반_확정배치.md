# Task 03 — 앵커 기반 확정 배치

## 목적

유효한 벽 후보에만 캐릭터 하나를 확정하고, AR tracking 변화에도 세션 동안 같은 물리 벽 위치에 남게 한다.

## 선행 조건

- [ ] Task 02의 수직 벽 후보·프리뷰 동작

## 작업

- [ ] `<UNITY_PROJECT_ROOT>/Assets/Scripts/AR/WallPlacementController.cs`를 만든다.
- [ ] 상태를 `Scanning → CandidateValid → Placed → Repositioning`으로 명확히 관리한다.
- [ ] 확정 탭 시 hit pose/plane에 연결된 `ARAnchor`를 생성하고 캐릭터를 anchor 하위에 둔다.
- [ ] anchor 생성 실패 또는 tracking 제한 시 사용자에게 사유를 알리고 프리뷰 상태로 복귀시킨다.
- [ ] 한 세션에 하나의 캐릭터만 허용한다.
- [ ] 재배치와 Reset을 제공하고, 이전 캐릭터와 anchor를 안전하게 정리한다.
- [ ] Plane 병합·업데이트·subsumption이 일어나도 배치 객체가 월드 원점으로 튀거나 중복되지 않는지 로그를 남긴다.

## 수용 기준

- [ ] 유효한 벽 탭 한 번당 캐릭터 1개만 배치된다.
- [ ] 배치 뒤 0.5~1.5m 이동하고 시선을 벽에서 돌렸다 다시 보아도 같은 벽의 상대 위치·방향에 남는다.
- [ ] Reset 뒤 캐릭터 및 anchor 수가 0이고 상태가 `Scanning`으로 돌아간다.
- [ ] 앱 실행 중 plane 갱신이 발생해도 중복·원점 이동·예외가 없다.

## 제외

앱 재시작 후 복원, 다른 기기와 공유, Cloud Anchor.
