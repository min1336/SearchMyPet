# Task 01 — AR 수직 벽면 탐지 스파이크

## 목적

빈 AR 씬에서 수직 벽이 실제 기기에 탐지되는지 먼저 증명한다. 이 Task는 배치 게임을 만들기 위한 작업이 아니라 가장 큰 기술 위험을 제거하는 스파이크다.

## 환경별 검증 경계

| 환경 | 담당 작업 | 완료로 인정할 수 있는 증거 |
| --- | --- | --- |
| Windows + Unity | 코드·씬 작성, 패키지 resolve, 컴파일, 선택적 XR Simulation, `outputs/ios-xcode-wall-placement`로 iOS Xcode 프로젝트 export | 구현 및 export 준비 증거만 인정한다. |
| Mac + Xcode | Xcode 프로젝트 열기, Signing Team·Bundle ID·Deployment Target 확인, Debug 빌드 및 iPhone 설치 | Xcode 빌드·서명 로그를 인정한다. |
| iPhone 14 / iOS 27.0 | 카메라 권한, AR 세션 시작, 실제 수직 벽 탐지, Plane 시각화·로그, 실패 UX | Task 01의 최종 Go/No-Go 증거로 인정한다. |

Windows XR Simulation은 로직 확인을 돕는 선택적 보조 증거이며, 실제 ARKit 카메라·추적·벽면 탐지 성공을 대체하지 않는다.

## 선행 조건

- [x] Task 00의 플랫폼·패키지·테스트 기기 결정

## 작업

- [x] `<UNITY_PROJECT_ROOT>/Assets/Scenes/WallPlacementValidation.unity`를 만든다.
- [x] AR Session, XR Origin(AR), AR Camera를 배치한다.
- [x] `ARPlaneManager`, `ARRaycastManager`, `ARAnchorManager`를 구성한다.
- [x] Plane detection을 `Vertical` 중심으로 설정한다. 수평 평면은 배치 후보로 쓰지 않는다.
- [x] 개발용 Plane 시각화와 탐지 상태 문구를 추가한다.
- [x] 권한 거부, AR 미지원, 세션 실패에 빈 화면 대신 재시도 가능한 안내를 표시한다.
- [x] iOS ARKit이 노출한 실제 카메라 줌 범위만 사용해 `0.5× / 1× / 2×` 렌즈 선택 UI를 구성한다.
- [ ] 실제 벽을 20~30초 스캔해 수직 Plane 탐지 수와 상태를 기록한다.

## 수용 기준

- [ ] 선택한 실기기에서 카메라 권한을 얻고 AR 세션이 시작된다.
- [ ] 실제 수직 벽에서 하나 이상의 수직 Plane이 탐지되고 개발용 시각화 또는 로그로 확인된다.
- [ ] 권한 거부·미지원 상황이 예외나 무응답이 아닌 안내 UI로 처리된다.
- [ ] 렌즈 선택값을 바꾼 뒤에도 카메라 영상과 수직 Plane 탐지가 정상으로 유지되는지 실기기에서 확인한다.

## 제외

최종 UI, 캐릭터 모델, 탭 배치, 영속성.

## Mac / iPhone 재검증 순서

- [ ] Windows에서 새로 생성된 `outputs/ios-xcode-wall-placement` 폴더 전체를 Mac의 새 로컬 폴더로 복사한다. 이전 Xcode 산출물과 섞지 않는다.
- [ ] Mac 터미널에서 `xcode-select -p`와 `xcodebuild -version`을 확인한다. ARKit 6.5.0 요구사항에 따라 Xcode 26.0 이상을 사용한다.
- [ ] `Unity-iPhone.xcodeproj`를 열고 Scheme은 `Unity-iPhone`, Destination은 연결된 iPhone 14로 선택한다.
- [ ] Signing Team, 고유 Bundle ID, Automatically manage signing을 확인한 뒤 `Product > Clean Build Folder`, `Cmd+B`를 실행한다.
- [ ] `lib_burst_generated.a`의 `No platform load command`가 경고로만 남으면 기록하고 계속한다. 뒤이어 `ld: error`, Undefined symbols, Burst compiler 실패가 나올 때만 빌드 차단으로 판정한다.
- [ ] 빌드가 성공하면 `Cmd+R`로 설치하고, 카메라 권한 승인 후 밝고 질감 있는 수직 벽을 1~2m 거리에서 20~30초 스캔한다.

## 완료 증거

- 기기/OS/앱 빌드:
- 벽 재질·조명:
- 빌드 로그: Unity Editor 컴파일 오류 없음(사용자 확인), `Assembly-CSharp` 및 `Assembly-CSharp-Editor` 빌드 경고 0개·오류 0개.
- iOS Xcode 링크: 첫 시도에서 ARKit 네이티브 라이브러리의 `swiftCompatibility51/56/Concurrency` 심볼 링크 실패. 생성된 `.pbxproj`에 `DEVELOPER_DIR` 기반 Swift 런타임 검색 경로가 누락된 것을 확인해 Unity export 후처리 및 누락 검증을 추가했다. 깨끗한 폴더로 Unity iOS export 성공(3분 42초, 약 1.55GB) 및 두 Xcode 타깃의 설정 반영을 확인했으며, Xcode 26+ 재빌드는 대기 중이다.
- 20~30초 캡처 또는 스크린샷:
- Plane 탐지 로그: 2026-07-28 Windows XR Simulation에서 `ARSession=SessionTracking`, XR Input Subsystem 실행, 카메라 위치·회전 입력 활성화, `Vertical` 탐지 모드를 확인했다. 시뮬레이션 카메라를 벽 쪽으로 이동한 뒤 `alignment=Vertical`, `tracking=Tracking`, 수직 Plane 1개 추가 로그를 확인했다. iPhone 14 / iOS 27.0의 ARKit 실기기 검증은 대기 중이며 Windows 결과만으로 Task 01을 완료 처리하지 않는다.
- 렌즈 UI: Unity iOS export에 `SearchMyPetARCameraLens.mm`이 포함되며, iOS 16+의 ARKit configurable capture device에서 실제 최소/최대 줌을 읽고 범위 안의 `0.5× / 1× / 2×`만 표시한다. iPhone 실기기 렌즈 전환 및 AR 추적 재검증은 대기 중이다.
