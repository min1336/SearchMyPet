# Task 02 — 벽면 후보와 프리뷰 UX

## 목적

사용자가 배치 가능한 수직 벽을 명확히 이해하고, 바닥·책상에는 절대 배치할 수 없게 한다.

## 선행 조건

- [ ] Task 01의 수직 Plane 실기기 탐지 증거

## 작업

- [ ] `<UNITY_PROJECT_ROOT>/Assets/Scripts/AR/PlacementReticle.cs`를 만든다.
- [ ] 화면 중앙 또는 터치 지점에서 `TrackableType.PlaneWithinPolygon` raycast를 수행한다.
- [ ] raycast 결과의 `ARPlane.alignment`가 `Vertical`인 경우에만 유효 후보로 판정한다.
- [ ] 미탐지 상태에는 “벽면을 천천히 비춰 주세요”, 유효 상태에는 “탭하여 벽에 배치”를 표시한다.
- [ ] 유효/무효 레티클 색과 배치 버튼 활성 상태를 구분한다.
- [ ] 너무 작은 초기 Plane과 제한된 tracking 상태에는 즉시 확정 배치하지 않도록 안정화 조건을 둔다.
- [ ] hit pose와 벽 법선을 사용해 프리뷰의 위치·방향을 계산한다. 월드 up은 유지한다.
- [ ] 벽 내부 끼임과 z-fighting을 피하도록 벽 바깥쪽 법선 방향으로 작은 오프셋을 둔다. 정확한 값은 `WallPlacementConfig`에 기록한다.

## 수용 기준

- [ ] 바닥·테이블 raycast에서는 배치 가능 상태나 확정 동작이 나타나지 않는다.
- [ ] 실제 수직 벽에서만 레티클과 배치 안내가 유효 상태가 된다.
- [ ] 프리뷰는 벽을 향해 눕거나 뒤집히지 않고, 탭 전에 최종 위치·방향을 예측할 수 있다.

## 제외

Occlusion, 최종 Plane 렌더링, 실제 페인팅.
